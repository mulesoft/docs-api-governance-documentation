= Getting Started with Anypoint API Governance
:page-notice-banner-message: Use the enhanced MuleSoft experience to manage and apply governance policies across your portfolio, with consistent strategies across providers. <a href="https://docs.mulesoft.com/general/exp-governance-work-with-strategies" target="_blank" rel="noopener">Learn more</a>.

[NOTE]
We updated the terminology in the API Governance UI to reflect a broader range of asset types. Where Governance previously used "APIs," it now uses "Services." There are no changes to functionality. During this transition, you may see a mix of the new and previous terms in our documentation.


After you become familiar with the UI and concepts covered in the xref:index.adoc[Anypoint API Governance Overview], you're ready to get started governing your APIs.

[[verify-permissions]]
=== Verify Your Permissions

To use API Governance you must have either _Governance Viewer_ or _Governance Administrator_ permission.

* *API Governance* > *Governance Viewer*
+
This permission allows API Governance users, such as API developers and architects, to:

** View the Governance console conformance summary.
** View the *Governed Services* page with the list of governed services that they have permission to view.
** Download a detailed governance report for their APIs in CSV format.
+
* *API Governance* > *Governance Administrator*
+
This permission allows API Governance users, such as API governance and security officers, full access to API Governance.

Anypoint Platform organization administrators are allowed full access to API Governance regardless of their API Governance permission settings.

Higher level permissions override the *Governance Viewer* permission. If a user has the *Governance Administrator* permission or is an organization administrator, setting the *Governance Viewer* permission for them does not limit their permissions.

[[opt-in]]
=== Opt in to Additional Functionality

If you're an administrator and have an opt-in banner in the Governance console, opt in to get additional functionality for your business groups (organizations). See the xref:release-notes::api-governance/api-governance-release-notes.adoc##oct-17-2023[API Governance Release Notes entry for October, 17 2023].

This documentation covers the full product functionality that is available after the opt-in.

[[third-party-gateway-prereqs]]
=== Set Up Third-Party Gateway Connectivity (Optional)

[NOTE]
====
This section describes features available only in the enhanced MuleSoft experience. The *Platform* > *Providers* navigation and the *Connect to a Provider* wizard are not available in the classic Anypoint Platform UI. See xref:general::exp-governance-work-with-strategies.adoc[].
====

If you manage APIs on third-party gateways such as Kong, Apigee, AWS API Gateway, or Akamai, connect those providers before you begin governing their APIs.

To connect a third-party gateway provider:

. In *Anypoint Platform*, navigate to *Platform* > *Providers*.
. Click *Connect to a Provider* and follow the three-step wizard:
.. *Choose Provider* — Select your gateway provider (Kong, Apigee, AWS, Akamai, or another supported provider).
.. *Connection Setup* — Enter your credentials to authenticate and discover available platforms. Credentials are stored securely and used only for discovery scans.
.. *Apply Policy* — For supported providers such as Akamai, a correlation policy may be applied automatically across your Omni Gateway environments. For other providers, confirm the connection.
. After your connection is live, a scanner is created that discovers APIs from the connected provider and adds them to your portfolio.

NOTE: When scanner credentials are configured with read-only permissions, policy application for APIs on that provider is also read-only. To enable full policy management, use *Update Credentials* in the scanner settings to supply credentials with write access.

== Govern Your APIs

Govern your APIs using these steps:

. xref:add-tags.adoc[Identify] APIs to filter for governance by using tags and categories in Exchange.

. xref:create-profiles.adoc[Configure governance profiles] to identify which rulesets to apply to which APIs.
.. Consider saving your profiles as draft to test settings before revealing their targeted APIs' conformance information across Anypoint Platform.
.. After you test settings using draft profiles, xref:create-profiles.adoc#activate-draft-profile[activate the profiles] to notify developers and reveal the resulting conformance information across Anypoint Platform.

. xref:monitor-api-conformance.adoc[Monitor governance conformance status] in the Governance console.
** View the APIs targeted by each draft profile to assess conformance impacts for that profile and download the associated CSV file report.
** View summary information in the Governance console and in validation reports.

. xref:find-and-fix-conformance-issues.adoc[Find and fix conformance issues]:
* In API specifications in Anypoint Code Builder, Design Center, and Exchange as you design your APIs
* In API instances in API Manager at deployment time
* In API catalog information in Exchange asset portal information
* In API documentation in Exchange asset portal documentation

. xref:create-custom-rulesets.adoc[(Optional) Create custom rulesets] to more effectively govern APIs for your business groups (organizations).

. xref:cli-command-list.adoc[(Optional) Install and run CLI commands] to automate governance as part of your CI/CD pipeline and to more easily create custom rulesets.

. (Optional) Use the API Governance Experience API to implement custom API-based solutions that access a subset of API Governance functionality. For example, you can use the experience API to list governance profiles and retrieve API conformance status information. Access the experience API in Exchange in your preferred Anypoint Platform control plane:

[[govern-third-party-apis]]
== Govern Third-Party APIs

[NOTE]
====
This workflow requires the enhanced MuleSoft experience. The *Governance Strategies* page, *Policy Library*, and cross-gateway reporting described here are not available in the classic Anypoint Platform UI. See xref:general::exp-governance-work-with-strategies.adoc[].
====

If your organization runs APIs on third-party gateways (Kong, Apigee, AWS API Gateway, or Akamai), use the following workflow after completing the <<third-party-gateway-prereqs,provider connection prerequisite>>.

NOTE: This workflow applies to users managing APIs on external gateway providers. If you manage only MuleSoft-native APIs, follow <<govern-your-apis,Govern Your APIs>> instead.

. *Connect the provider* — In *Platform* > *Providers*, connect to your gateway provider as described in <<third-party-gateway-prereqs>>. After the connection is live, a scanner automatically discovers and imports APIs from that provider into your portfolio.

. *Verify discovered APIs* — In the Portfolio Overview on the *Governance* dashboard, confirm that your provider's APIs appear under the *Discovered* tier. APIs discovered from a connected provider are available for governance without requiring manual Exchange registration.

. *Create a governance strategy targeting that gateway* — In *Governance* > *Governance Strategies*, create a new governance strategy and use the *Gateway/Provider* filter under *Define Filter Criteria* to scope the strategy to APIs on your specific gateway (for example, Kong or Apigee). Select the rulesets to apply.

. *Monitor conformance and apply policies* — After the strategy is active, monitor conformance status in the *Governance Strategies* page. To apply policies directly to gateway instances, use the *Policy Library* (*Platform* > *Policy Library*) and follow the Select Policy → Configure Policy → Select Instances → Review & Apply workflow.
+
NOTE: If your scanner credentials are read-only, the *Apply Policy* action is disabled. To enable policy application, go to *Platform* > *Providers*, select the scanner, and click *Update Credentials* to provide credentials with write access.

. *Export cross-gateway reports* — Export conformance and policy audit reports from the *Governance Strategies* page. See xref:monitor-api-conformance.adoc#gov-cross-gateway-export[Cross-Gateway Policy Audit Export].
