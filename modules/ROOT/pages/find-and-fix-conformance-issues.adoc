API Governance helps you continually improve your organization's conformance by providing tools and guidance for finding and fixing conformance issues.

Governance admins typically:

* Initiate validation of APIs against rulesets in xref:create-profiles.adoc[API Governance] for all supported API aspects.
* View conformance information in the <<governance-validation-report,validation report in API Governance>>.
* Notify developers or implementors about conformance issues.

Developers and implementors typically:

* Initiate validation of API specifications against rulesets in xref:find-conformance-issues.adoc[Anypoint Code Builder or Design Center].
* View conformance information for each rule in the context of the open specification project.

* Fix conformance issues using the following:

** xref:find-conformance-issues.adoc#fix-conformance-issues[Anypoint Code Builder or Design Center] for specifications
** xref:fix-documentation-conformance-issues.adoc[Exchange] for documentation
** xref:fix-catalog-info-conformance-issues.adoc[Exchange] for catalog information
** xref:fix-instance-conformance-issues.adoc[API Manager] for instances

Regardless of which tasks you're responsible for in governance for your organization, you can view conformance information for APIs that are centrally governed by API Governance in the following places in Anypoint Platform:

* <<governance-validation-report,Validation reports>> in API Governance or API Manager
* <<view-conformance-in-exchange,Conformance Status pages>> in Exchange for specifications
* <<view-governed-apis-for-rulesets,Governed Services pages>> in Exchange for rulesets

[[third-party-api-conformance]]
== Find Policy Drift on Third-Party API Instances

[NOTE]
====
This section describes features available only in the enhanced MuleSoft experience. The *Governance Strategies* page, *Platform* > *Providers*, and *Governance* > *Governance Strategies* > *Policy Library* are not available in the classic Anypoint Platform UI. See xref:general::exp-governance-work-with-strategies.adoc[].
====

If you manage APIs on third-party gateways (Kong, Apigee, AWS API Gateway, or Akamai), API Governance can detect policy drift — differences between the policies defined in your governance strategy and the policies actually applied on the gateway instance.

To find policy drift on third-party API instances:

. In *Governance* > *Governance Strategies*, select the active governance strategy that targets your third-party gateway provider.
. In the governed services list, look for services with a *Not Conformant* or *Policy Drift* indicator.
. Click *View Report* for a service to see the detailed conformance breakdown, including which policies are missing or misconfigured on the gateway instance.

Common causes of policy drift on third-party instances include:

* Policies applied manually on the gateway that conflict with or differ from the centrally defined governance strategy.
* Scanner credentials that were updated on the gateway but not reflected in the Anypoint Platform scanner configuration.
* Policies applied through the *Policy Library* that are not yet reflected in the governance strategy scope.

[[update-scanner-credentials]]
=== Update Scanner Credentials to Enable Policy Application

When scanner credentials are read-only, API Governance can report on conformance but cannot apply or remediate policies programmatically. The *Policy Application Status* for affected services shows *Read-Only*.

To fix this, update the credentials for the associated scanner:

. In *Platform* > *Providers*, locate the provider connection for the affected gateway (Kong, Apigee, AWS, or Akamai).
. Select the scanner and click *Update Credentials*.
. Enter credentials that have write access to the gateway's policy management API.
. Save the credentials. The scanner authenticates on its next scan cycle, and the *Policy Application Status* updates from *Read-Only* to *Enabled*.

NOTE: Credentials are stored securely and used only for discovery scans and policy application. After updating credentials, the *Last Scan Auth* indicator in the scanner settings reflects the authentication result.

=== Apply Policies Using the Policy Library

As an alternative to waiting for automatic policy application through a governance strategy, apply policies directly to specific gateway instances using the *Policy Library*:

. In *Governance* > *Governance Strategies* > *Policy Library*, browse or search for the policy to apply.
. Follow the four-step apply workflow:
.. *Select Policy* — Choose the policy from the Universal policies or category-based sections (Access and Security, Performance and Cost, Data Privacy and Integrity, Compliance and Observability).
.. *Configure Policy* — Set the policy parameters.
.. *Select Instances* — Choose the specific gateway instances to apply the policy to.
.. *Review & Apply* — Review your selections and apply.

NOTE: Universal policies apply to any service, including scanned and federated APIs from third-party providers.

== Browser Resource Limits for Governance Validation

When running governance validation in the web browser, the process is subject to browser memory limits. For large or complex API specifications, the browser can exceed its resource limit and stop the validation process. In this scenario, the dialog displays a "Validation failed" error. This is expected behavior when the browser can't allocate additional resources for validation.

To avoid this limitation, run governance validation in Anypoint Code Builder Desktop, which can use more system memory and CPU than a browser tab.
